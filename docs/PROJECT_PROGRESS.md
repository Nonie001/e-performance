# สถานะระบบ E-Performance

ตรวจจากโค้ดใน repository วันที่ 5 พฤศจิกายน 2569 เอกสารนี้แยกสิ่งที่มีในโค้ดออกจากงานที่ยังต้องสร้างหรือยืนยันบนระบบจริง

| ขั้นตอน | สถานะจากโค้ด | สิ่งที่ยังต้องทำ |
|---|---|---|
| เข้าสู่ระบบและออกจากระบบ | มีหน้า Login, API, session และ Logout | ทดสอบกับบัญชีและ deployment จริงตามสิทธิ์ |
| เปลี่ยนรหัสผ่านครั้งแรก | มีหน้าและ API; รองรับการข้ามพร้อมแจ้งเตือน | ตัดสินใจนโยบายว่าจะอนุญาตให้ข้ามหรือบังคับเปลี่ยน |
| ข้อมูลพนักงานและคะแนน HR ของตนเอง | Dashboard อ่านผ่าน Apps Script | ยืนยันความครบถ้วนของข้อมูลและคะแนนจริงรายคน |
| เปิดแบบประเมินตนเอง | Dashboard เปิด Google Form ตามลิงก์ของพนักงาน | สถานะส่งแบบประเมินและคำตอบรายข้อยังไม่แสดงในเว็บ |
| รายชื่อลูกน้องและคะแนนรอบ 2 | Dashboard อ่านสายหัวหน้า–ลูกน้องและไฟล์คะแนนหัวหน้า | ยืนยันการจับคู่คะแนนจริงทุกไฟล์; แยกสถานะจากช่องคะแนนว่าง |
| หน้าหัวหน้าตรวจทานรายคน | มี route `/supervisor/review/[employeeId]` และ Apps Script เวอร์ชัน 14 ที่ตรวจสิทธิ์สายบังคับบัญชา | เพิ่มการอ่านสถานะส่งจากไฟล์ EF-XX ในโค้ดแล้ว; ต้องตั้งค่าแหล่งไฟล์ Deploy เวอร์ชันใหม่ และทดสอบกับบัญชีหัวหน้างานจริง |
| หัวหน้าให้คะแนนและส่งกลับแก้ไข | ยังไม่มีในเว็บ | กำหนดแบบประเมินตาม EF Code, การบันทึกคะแนนและเหตุผลที่ส่งกลับ |
| ฝ่าย BSE / GM / MD อนุมัติ | ยังไม่มี route หรือ API | หน่วยงาน BSE ให้ผู้จัดการฝ่ายตรวจสอบ/แก้ไข/อนุมัติก่อนส่ง GM; หน่วยงานอื่นส่ง GM ได้เลย แล้วต่อ MD ตามเงื่อนไข |
| HR เปิด–ปิดรอบและตั้งเกณฑ์ | ยังไม่มีหน้า Admin | กำหนดปี รอบ วันที่ เกณฑ์ และวิธีจัดการข้อมูลหลัก |
| รายงานและประวัติย้อนหลัง | ยังไม่มี | สรุปรายคน ทีม หน่วยงาน และเก็บผลแต่ละรอบ |
| ข้อมูลปี 2569 | มีลิงก์ไฟล์ต้นทางใน `SHEET_LINKS.local.md` | ยังไม่ได้เชื่อมเข้ากับแอปที่แสดงผลปี 2568 |

หน้า `/preview/round-two` เป็นตัวอย่างหน้าตาที่ใช้ข้อมูลสมมติ ไม่ใช่ผลคะแนนจริง

## งานถัดไปที่ต่อกับระบบปัจจุบัน

1. ตรวจข้อมูลหน้าตรวจทานจริงกับบัญชีหัวหน้างานและลูกน้องในสาย
2. กำหนดแหล่งข้อมูลและสถานะการส่งประเมินตนเองให้ชัดเจนก่อนทำปุ่มให้คะแนนหรือส่งกลับ
3. เพิ่มการให้คะแนนรอบ 2 และการบันทึกสถานะ จากนั้นจึงต่อสายอนุมัติ BSE (เฉพาะหน่วยงาน BSE) → GM → MD ตามเงื่อนไขใน `PROJECT_FLOW.md`
4. สร้างเครื่องมือ HR สำหรับตั้งรอบและรายงานเมื่อ workflow คะแนนครบ

ทุก route ที่แสดงข้อมูลลูกน้องต้องตรวจ session และยืนยันว่ารหัสพนักงานเป้าหมายอยู่ใต้หัวหน้าที่เข้าสู่ระบบ ไม่ใช้เพียงรหัสพนักงานใน URL เป็นสิทธิ์เข้าถึง
